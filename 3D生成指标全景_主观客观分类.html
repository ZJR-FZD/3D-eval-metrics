② 语义对齐（跟 instruction 比）

拿渲染图跟文本 prompt 算相似度，问"生成的是不是文字要的那个东西"。参照物必须是 instruction 文本——这是本维度唯一的准入标准。

这个维度有两种手段——客观手段用 embedding 余弦（本节），主观手段用人 / VLM 判断（见 S1）。

维度内的指标测什么依据 / 手段公式方向出处代码
CLIP Score渲染图与文本语义一致六视图 + CLIP 编码，图 vs 文本 Pavg=(1/6)ΣCLIP(I_i,P)；max=max_i↑CodeGen-3DB1_clip_score.py
CLIP-T文→形一致渲染图 vs prompt 进 CLIP余弦↑sketch-to-3D 综述B1_clip_score.py
CAD 规格一致性生成 .FCStd 是否含 instruction 点名的特征名 + 尺寸解析 .FCStd(zip/Document.xml) 特征树+参数，vs 文本精确匹配特征名F1 + 尺寸命中率 加权↑CAD 参数化任务B2_cad_spec_consistency.py
两种手段，同一维度：CLIP 是「渲染图 vs 文本」的模糊语义余弦；CAD 规格一致性是「特征树 vs 文本」的结构化精确匹配（特征名 F1 + 尺寸容差命中率）。参照物同为 instruction → 都归 ②。

Blender 里的同类项（BlenderWorld）：Blender 也有"规格一致性"，但不是单一指标，而是拆成很多条二元 rubric 判据。其中 evidence_type=scene_summary 的一类由结构判官用 bpy 打开 .blend 读内部字段判定——shape keys、drivers、Geometry Nodes 参数、三角面预算、UV 布局、材质节点图、精确 mm 尺寸、物理设置等。参照物同样是"任务预定义规格"（等价于 instruction）→ 本质归 ②；另有 render 类判据靠视觉判官看渲染图。
与 CAD 的区别：.FCStd 是 zip+xml 可直接解析；.blend 是二进制，必须用 bpy 探针读取，无法脱离 Blender 环境。

④ 拓扑 / 物理 / 工程可用性（自检）

这是唯一不需要参照物的维度——不要 GT、不要文本、不要人，只看生成物自己。"能不能用"= 能不能被下游 3D 打印 / 仿真 / 游戏 / 制造流程直接接受。分三层，全是程序可算：

① 拓扑 = 网格数据的"完整性体检"（纯数学，翻开文件就能查）：像检查气球漏不漏气——表面破洞吗（Watertight）？一条边被 3 个以上面共享吗（Manifold）？面与面互穿吗（自交）？

关键：一个跟真值长得一模一样（Chamfer≈0）的椅子，导出时丢一个面，体检照样不及格——这就是几何保真测不出的盲区。

② 物理 = 放进仿真环境实测：受重力站不站得住（Stability，重心太高的杯子一碰就倒）？装配零件穿不穿模（Collision / Penetration）？

③ 工程可用性 = CAD 的 DFM / DFA 检查（关键补充："设计可用性"里可制造 / 可装配 / 功能这部分根本不用人判，程序就能算）：

  • 可制造性（DFM）：最小壁厚、拔模角（能否脱模）、刀具可达性、最小孔径——几何规则检查；
  • 可装配性（DFA）：零件间隙 / 配合、装配方向可达——求交 + 距离计算；
  • 功能：机构自由度 DOF、运动学 / 受力——仿真。

榜单（MUSE / BlenderWorld）用 VLM rubric 打这些分，只是没有 CAD 内核时的近似手段，不代表它们天生主观。

主观评判的两个维度

VLM 裁判的输入是渲染图（不是 .blend）；有的还做重渲染一致性校验，防"只交好图、几何是垃圾"。

S1 感知语义一致性（Perceived instruction alignment）

  • 评什么：人 / VLM 主观觉得符不符合文字要求。
  • 依据：渲染图 + instruction 文本给裁判。
  • 关键点：这就是唯一干净的"② 的主观版"——同一个维度、同一个参照物（文本），只把裁判从 CLIP 余弦（客观）换成 VLM / 人（主观）。
  • 可用手段：VLM 按 prompt 逐条打分、MOS。

S2 感知视觉质量（Perceived visual quality）—— 含真实感 + 审美

  • 评什么：人 / VLM 看渲染图的整体印象——像不像真的、有无伪影 / 破面、好不好看、专不专业、风格恰不恰当。形状 + 材质 + 光影 + 审美全算进去。
  • 依据：渲染图（主视图 + 多视图），对照参考图或纯靠感知；judge rubric。
  • 出处：CodeGen-3D 的 GPT-4o 成对偏好、Frontier 的 VLM visual fidelity、MUSE rubric 审美条款、BlenderWorld dimension 评分。
  • 可用手段：成对偏好、Rubric 打分、MOS。
主观评判手段：
   • 打分量表：MOS（1–5 均值）、Rubric（0–4 锚点 × 权重）
   • 两两对比：Pairwise win rate、Elo 排名
   • 裁判来源：Human judge / VLM judge（GPT-4o 等，看渲染图不看 .blend）
